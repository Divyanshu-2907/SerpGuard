SerpGuard

API live

A Ruby on Rails API that pulls the checkable claims out of AI-generated text or code and rules on each one against live Google results — claims extracted by Claude, evidence from SerpApi, verdicts cached in MongoDB. Paste something below; it calls the same public endpoint any client would.

What you just called

One POST, three upstream calls per unseen claim - five if a query misses

Claims, not vibes

Claude splits the input into discrete claims and restates each so it stands alone as a search query — resolving pronouns, keeping version numbers and figures exactly as written. Correcting them would defeat the point.

Judged on sources only

The verdict prompt is told to rule against the returned snippets and not from the model's own knowledge. Otherwise a fact-checker just launders its own priors back as a verdict.

Unreadable ≠ unconfirmed

unconfirmed is a real finding: the evidence was thin. A verdict that could not be parsed raises verification_failed instead. There is no code path that quietly turns one into the other.

Cited or dropped

A source URL is kept only if it is one we actually handed to the model. An invented link is dropped and logged rather than passed on as a citation — the verdict still stands on the snippets.

Verdicts are cached

Each claim is keyed by a SHA256 of its normalized text, unique-indexed in MongoDB. Check the same claim twice and the second answer comes back cached: true with zero upstream calls.

A method that isn't there

For a code_api claim whose method name appears in no result, the verdict is contradicted, not unconfirmed. A real method name returns something for a search of its own name — an ordinary fact has no such guarantee, which is why the rule stops at code.

Retries, once

Timeouts, connection resets, 429s and 5xx get exactly one retry, shared by both API clients. A query whose results come back about a different subject also gets one rewrite — and only then. A 4xx that cannot succeed on a second identical attempt is never sent twice.
